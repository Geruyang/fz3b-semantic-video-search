# 客户端推理 FPS 改为最近十张

原设备状态使用累计完成帧数除以从开始推理到当前时刻的总时间，包含启动准备、流水填充，且停止后分母仍增长，造成显示缓慢上升或下降。上传视频原来也使用整个任务的结果间隔平均，无法及时反映当前速度。

新口径为最近十张真实图像的完成间隔：`10 / (最新完成时间 - 十张之前的完成时间)`，保留十一项时间边界，覆盖十个间隔。取整体吞吐率，不对瞬时 FPS 做算术平均。启动后先显示“采样中”，满十个间隔后才显示 FPS，避免最初两张成对交付的极短间隔导致虚高；每次开始或调频恢复都清空窗口。板端暂停或停止后的值保留最后一个窗口的测量结果，并通过原有状态文案说明是否运行。

实时录像画面下方、设备参数、上传视频分析和预计剩余时间统一使用窗口 FPS。上传视频使用板端完成时间，避免网络接收批次导致虚高。相机帧率、推理性能、模型、PL 和 R5 固件没有因显示口径改动而提速或改变。

维护实现为 HOST/PS 各自同内容的 `vision_app/recent_fps.py`。板端只在完成一张图像时更新有界十间隔窗口（十一项时间边界），与原状态快照共享锁；重新开始时清空。额外存储固定，不增加图像传输。

验证：92 项应用回归通过（既有一项旧安装工具测试仍排除）。新增测试覆盖启动等待排除、近期速度替换旧历史、不均匀间隔的正确吞吐率、窗口清空和设备状态读数。实板逐个核对状态中的 FPS 与真实摄像头结果完成时间，见 `fps-real-board.json`；部署和新 EXE 验证见同目录的 FPS 回执。

板端正常排空后只更新应用 Python 源码，不改变当前 RTL008、加载器、CPU 默认频率或启动镜像。主机唯一发布位置仍为 `deliverables/vision-console/FZ3BVisionConsole`。

打包首次检查发现依赖尚未安装完成时提前构建漏收集分词资源，已补充构建前完整性检查并重新构建、自检。正式客户端仅在全部验证通过后替换。
